# 场景参数构建

## 读取当前契约

只有 ImageVersion 已由用户明确确认后，才能调用 `gateway.image_versions.get_request_schema`，并复用详情中的 `constraint_override_schema`、`constraint_override_defaults`、`constraint_presets`、`limits`、`supported_map_providers`、`base_credit_cost` 和 `duration_credit_per_10s`。唯一候选、Agent 推荐或已调用详情都不能替代用户确认。

按固定顺序处理：

1. 读取并解析当前 ImageVersion 的 `request_schema`；
2. 将创建请求顶层字段、作为 `request_payload` 子结构的原始 `request_schema`，以及规范化为对象属性的 `constraint_override_schema` 组合成当前草稿的内部校验视图；
3. 根据该视图理解业务字段、收集缺口并构建 `request_payload`；
4. 只有内部校验视图已经完成，且约束相关的业务目标、硬规则和可接受取舍已经明确，才进入约束方案推荐与罚分设置。

内部校验视图只用于当前会话构建和辅助校验，不修改 Gateway 返回的原始 Schema，不写入项目，不新增 Gateway 创建字段。Schema 获取失败、所属 ImageVersion 不一致或无法规范化时停止后续参数构建，也不得提前推荐约束方案。

- 递归理解对象、数组、`required`、类型、枚举、格式、范围和默认值。
- 按业务对象或源表分组提问；用户已提供完整结构时不要重复逐字段询问。
- 关键字段含义不确定时标为待确认，不凭相似名称、行业惯例或样例猜测。
- 只有 Schema 默认值或用户明确确认的值可以作为业务默认值。
- 请求结构完全服从当前 ImageVersion Schema。不得把某个历史引擎的对象组织方式、枚举语义或技术默认值固化为通用 Skill 规则。

## 用户可见枚举

枚举的用户可见名称和简短业务说明必须来自当前 ImageVersion Schema：

- 对用户只展示与当前语言匹配的名称和说明，不展示不必要的字段路径、机器值或枚举代码；
- 在会话内部保存用户选择对应的机器值，并只把机器值写入 `request_payload`；
- 需要用户选择时，先比较 ImageVersion 提供的各选项说明，提炼真正决定选择的业务差异，用一至三个简短业务问题询问，再把回答映射为机器值；不要直接要求用户从代码或陌生名称中选择；
- 如果选项说明涉及物料装载、卸载或回收，优先询问是否携带物料到现场，以及服务后物料是否增加、减少或需要带回；只使用 Schema 明确提供的语义，不在通用 Skill 中固化某个引擎的工单类型知识；
- 用户已经用业务语言明确表达选择时，仍用 ImageVersion 提供的名称复述确认；
- 完成可靠选择所需的中文名称、说明或关键差异缺失时，报告 ImageVersion 契约信息不足，不自行翻译、扩写或猜测枚举含义。

## 约束方案推荐与个别调整

只使用当前 ImageVersion 详情公开的 `constraint_presets`、`constraint_override_defaults` 和 `constraint_override_schema`，不要读取引擎文件、管理员接口或内部约束配置，也不要在 Skill 中固化某个引擎的方案名称、特点或罚分。

进入本节前必须同时满足：ImageVersion 已确认、当前版本 `request_schema` 已读取、内部校验视图已完成、与罚分选择有关的场景事实已足够。仅知道工单数、工程师数或其他规模信息时不得直接选择方案，应继续按 Schema 询问时间、技能、容量、稳定性、效率等实际相关信息。用户在门槛满足前主动询问约束方案时，先说明方案属于已选 ImageVersion，并完成上述步骤后再介绍。

1. 结合已确认的业务目标、不可放松规则和可接受取舍，比较各方案的中文 `title`、`description` 与公开 `scores`；给出一个首选方案、简短理由和主要取舍。
2. 用户询问“还有哪些约束方案”或不接受首选时，介绍当前 ImageVersion 返回的全部公开方案。默认只展示中文名称、说明和业务取舍，不展示机器 ID、原始字段名或整份分值表。
3. 选择方案后，以该方案的 `scores` 为基准，与 `constraint_override_defaults` 比较，只把不同的开放字段写入 `constraint_overrides`。不得把方案 ID、标题、说明或完整方案对象传给创建 tool。
4. 用户要求在方案基础上调整个别罚分时，只修改 `constraint_override_schema` 开放且校验通过的字段。用户给出明确值时按值校验；只有业务方向时，优先参考公开方案之间已经校准的差异提出最小必要调整，说明影响和最终罚分并纳入创建前确认，不静默调参。
5. 不因模糊偏好自动降低、关闭或改变 Hard 约束层级。用户明确要求此类调整时，先说明可能导致业务规则被违反的风险，再要求其确认具体最终值。
6. 用户的业务偏好、方案 ID 和推荐理由只保留在会话状态中；进入 Gateway 的仍只有合法 `constraint_overrides`。

`constraint_presets` 缺失、没有中文名称或说明、包含未开放字段或分值不符合 Schema 时，不猜测公开方案的含义或修正值；指出 ImageVersion 契约信息不足。无可靠方案可用时可以保留 ImageVersion 默认约束，但不得声称已经完成方案比较。

## 字段映射

| Gateway 字段 | 用户侧来源 | 转换规则 | 状态 | 依据或备注 |
| --- | --- | --- | --- | --- |

状态只使用：`已确认`、`待确认`、`缺失`、`需要转换`、`不适用`。

- 结合字段说明和脱敏样例确认业务含义。
- 标明 Schema 默认值或用户业务默认值的来源。
- 明确单位、时区、枚举和 ID 体系转换。
- 缺失关键字段不得用空字符串、零、当前时间或随机值掩盖。

## 业务 ID 与引用

`request_payload` 中工程师、工单、仓库、SKU、POI 等 ID 属于当前 ImageVersion 的业务标识，不是 Gateway 数据库系统主键：

- 用户或源数据已有非空 ID 时原样保留；若其不符合当前 Schema，列为阻断问题，不静默改写。不要要求用户为已具备来源 ID 的对象另报一个内部 ID。
- 只有当前 Schema 要求 ID 且来源确实缺失时才生成。生成一次后立即写入当前草稿，后续轮次和 revision 持续复用；不得因名称、数组顺序或其他可变展示字段变化而重新编号。
- 生成值先服从 Schema 明确声明的 `type`、`format`、`pattern`、`minLength` 和 `maxLength`。Schema 未规定外形时，只生成非空且在当前请求内唯一的不透明值；不得套用 Gateway 系统主键的内部生成规则，也不得硬编码某个历史页面组件使用过的前缀或大小写格式。
- 所有关联字段必须精确复用目标对象的最终 ID。创建确认前检查重复 ID、悬空引用和引用目标类型；不能靠生成一个新 ID 掩盖来源数据中的对象冲突。
- 地址解析候选已提供符合 Schema 的 POI ID 时保留该 ID；候选没有可用 ID、但当前 Schema 要求 POI ID 时再按上述规则生成一次。

## 地址解析与确认

用户已经提供可识别的地址或地点名称时，不要要求用户提供 POI ID 或经纬度。确认 ImageVersion 和其支持的 `map_provider` 后：

1. 对每个唯一地址调用 `gateway.map.geocode`，传入原始地址、已知城市和已确认图商；
2. 首次无候选时，先使用用户已提供的城市、区县和规范化地点名称进行有限重试；
3. 将地点分为“已解析”“需要选择”“需要补充”三组；已解析项按“原始地点 → 规范结果”集中列出，不在每行结尾重复写“是否确认”；
4. 多候选项集中列出可选结果，未解析项集中说明需要补充的城市、区县、道路或门牌信息；最后只用一句话统一请求确认已解析地点并处理其他两组；
5. 单一候选仍需纳入统一确认；重试后仍无候选才请用户补充地址；
6. 仍无法解析时继续请用户补充更精确的城市、区县、道路或门牌文本；只有用户主动提供精确点位时才接收 POI ID 或经纬度，不把坐标作为系统提问；
7. 只把用户确认的候选按当前 `request_schema` 映射到目标字段，不臆造 Schema 未定义的字段，也不把完整 POI 响应直接塞入 `request_payload`。

地址解析不是独立产物。每个已确认结果必须写回触发解析的业务对象地点字段或地点引用；不能只放入 `plan.pois`、网点或仓库后留下空的工程师起点、工单位置或其他关联字段。当前草稿已经包含可复用的已解析位置和明确对象关系时，直接补齐引用，不再次要求用户提供相同地址或坐标；只有一个位置可能属于多个对象且现有事实不能判定时才询问。

候选确认属于关键字段映射。已写入草稿的地址、POI 或坐标发生变化时，增加草稿 revision 并使旧创建确认失效。

## 地点结构

`plan.pois` 是否存在或必填、POI ID 是否必填，以及地点字段使用 ID 引用还是内嵌对象，全部由当前 ImageVersion Schema 决定：

- Schema 要求集中 POI 和 ID 引用时，为每个唯一地点生成稳定且唯一的业务 ID，填充 Schema 要求的 POI 字段，并在创建前验证所有引用能够解析；
- Schema 允许内嵌地点对象时，按当前契约构建，不为迎合某个历史引擎而强制改写成集中 `plan.pois`；
- Schema 同时允许多种结构但没有提供选择依据时，不凭经验猜测引擎偏好；把契约歧义作为阻断问题反馈。
- 不用空字符串、空对象、只有城市名称的对象或悬空 ID 充当位置。若 Schema 同时定义网点引用和独立起点字段，网点引用不自动替代起点；仅当用户事实明确两者为同一地点时，才复用同一已解析 POI。

## 网点、仓库和站点

只有业务确实使用网点、仓库或站点，且当前 Schema 定义了对应结构时才构建这些对象。不得因为字段存在、约束方案提到“同网点”，或用户只给出一个网点编号，就自动创建占位网点。

- 只要工程师、工单或其他对象包含网点引用，就必须存在对应网点对象，且所有引用在创建前都能解析到唯一对象。
- 每个实际使用的网点必须按当前 Schema 提供有效位置。若 Schema 使用 `plan.depos[].loc`，则该值不得缺失、为 `null`、空字符串、空数组或空对象；位置内部字段同样必须满足 Schema。
- 用户只提供网点名称、编号或地址时，复用地址解析流程获得候选位置并由用户确认，再按 Schema 写入坐标、POI 引用或内嵌位置；不得使用 `(0,0)`、随机坐标、名称字符串或空对象代替位置。
- 业务不需要网点且 Schema 不要求时，省略网点对象、网点引用和相关可选参数。Schema 仅要求数组容器且允许为空时使用空数组，不构造只有 ID 或名称的占位对象。
- Schema 强制要求网点及其位置，但用户无法提供或确认时，将其列为阻断问题并继续询问；不得为通过校验而伪造数据，也不得擅自删除 Schema 必填字段。
- 删除未使用网点时，同时删除工程师、工单和其他对象对它的引用；网点、位置或引用的任何变化都产生新草稿 revision 并使旧创建确认失效。

## 缺口与风险

分别列出：

1. 字段缺口：必填、类型、枚举或格式问题；
2. 映射缺口：含义、关联、单位、时区或过滤口径不确定；
3. 规模风险：可能超过 `limits` 或推荐规模；
4. 业务风险：时间冲突、资源不足、地址质量或容量等明显问题；
5. 安全风险：未脱敏样例、硬编码凭证或敏感日志。

这些只是辅助检查，Gateway 仍执行权威校验。

## 构建草稿

草稿只能包含：

```json
{
  "image_version_id": "<confirmed_image_version_id>",
  "map_provider": "<confirmed_map_provider>",
  "expected_solve_duration": "<ISO-8601 duration>",
  "request_payload": {},
  "constraint_overrides": {}
}
```

- `map_provider` 是创建请求顶层字段，不得放入 `request_payload`。
- 把“30 秒”等输入转换为 `PT30S` 后复述确认。
- 只有 `request_schema` 定义的引擎选项才能放入 `request_payload`。
- 用户接受平台默认行为时，不询问或主动写入 `build_transit_matrix`、`draw_route`、`matrix_mode`；只有用户明确要求改变行为且当前 Schema 允许覆盖时才提交非默认值。
- `constraint_overrides` 只包含选定公开方案相对默认值的差异，以及用户在其基础上明确确认、且由 `constraint_override_schema` 开放的个别调整；最终值等于默认值的字段省略。
- 用户偏好、约束方案 ID 或完整对象、完整约束配置、约束配置标识和求解模板不得进入创建草稿。

每次创建或修改草稿都增加内部 revision。revision 和“字段映射”等术语不向业务用户展示。大请求默认只展示业务对象、数量、地点、时间、规则和关键选项摘要；用户要求排障或查看技术细节时再展示完整 JSON、字段名或写入其指定的本地文件。

## 辅助检查

对当前 revision 输出一份检查结果，至少覆盖：

- Schema 必填、类型、枚举、格式、范围和额外规则；
- `limits` 声明的平台规模上限或推荐规模；
- 时间格式、时区、距离、重量、体积等单位；
- 业务对象 ID 唯一性和对象间引用关系；
- 每个用户已提供或 Schema 要求的地点都已写回对应业务对象，不存在仅已解析但未绑定的 POI；
- 实际使用的网点均有完整且已确认的位置，且不存在悬空网点引用或空位置占位对象；
- 图商、求解时长和约束覆盖项是否合法。
- 选定约束方案展开后的每个覆盖项是否开放且符合 Schema，用户个别调整是否覆盖在正确的方案基准上。

把结果分为“阻断问题”和“非阻断风险”。辅助检查不是独立 Gateway tool，也不能替代 Gateway 权威校验。

## 完成条件

进入任务执行前必须满足：

- Schema 属于当前已确认 ImageVersion；
- 必填字段没有缺口；
- 关键映射已经确认；
- 所有实际使用的网点都有符合 Schema 的已确认位置，且所有网点引用完整；
- 图商和求解时长已经确认；
- 约束方案推荐已经说明并写入当前草稿摘要；有多个公开方案时，当前选择将在统一的创建确认中由用户确认；
- 明显非法值已经修正；
- 辅助检查没有阻断问题；
- 风险为空或已由用户明确接受；
- 当前草稿 revision 已记录且尚未声称获得创建确认。
