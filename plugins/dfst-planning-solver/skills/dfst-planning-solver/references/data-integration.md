# 日常数据接入

## 使用条件

仅在用户要求形成重复运行流程时使用。先完成场景分析、ImageVersion 确认、实时 Schema 获取、字段映射和缺口确认，再修改用户工程。

确认以下信息：

- 数据源、表或文件结构、字段说明和对象关联；
- 过滤口径、单位、时区和运行频率；
- 目标工程语言、依赖、部署位置和密钥管理方式。

无法从项目判断技术栈时先询问。可以建议 Python 3，但不得擅自落地用户未确认的技术选型。

## 转换工具最低要求

在用户工程中生成最小实现：

- 从配置的数据源读取参与求解的数据；
- 按已确认映射转换为当前 `request_schema` 目标结构；
- 校验必填、类型、枚举、格式、单位和对象关联；
- 错误包含源记录标识和目标字段路径，但不输出完整敏感记录；
- 默认 dry-run，只生成或打印脱敏摘要，不提交任务；
- 真实提交必须通过显式 `--submit` 或等价开关；
- `GATEWAY_BASE_URL`、`GATEWAY_PAT` 等敏感配置来自环境变量或密钥系统；
- 提交后保存 `job_id`，支持状态查询并输出 Gateway 详情入口；
- 不实现绕过 Gateway 的引擎直连。

如果用户工程已有 JSON Schema 校验库，优先复用。新增依赖前说明用途并取得用户确认；没有校验库时至少检查已确认的关键字段，Gateway 继续承担完整校验。

## 测试与交付

小样本测试至少覆盖：

- 正常记录；
- 缺失必填字段；
- 非法枚举或时间。

交付时列出：

- 新增或修改文件；
- 环境变量和运行命令；
- dry-run 与真实提交的区别；
- 字段映射和未支持内容；
- 小样本测试结果；
- ImageVersion 或 `request_schema` 变化后的复查步骤。

客户专用 SQL 和转换代码只生成到用户工程，不沉淀到 Skill 包。日志不得输出 PAT、完整生产 payload 或敏感源记录。
